An audit should confirm what you already know about your controls. If it reveals surprises, preparation started too late.

## Before the audit

- **Know the scope:** which systems, processes, period and framework are in scope.
- **Run a self-assessment** against the framework's requirements, using a checklist or control matrix, and fix gaps early.
- **Map controls to evidence.** For every control, know exactly which artefact proves it works: a configuration screenshot, a log export, a ticket or a signed review.
- **Centralise evidence** in one repository with clear naming and version control.
- **Brief control owners** so they can explain their controls confidently.

## During the audit

Answer the question asked, provide evidence promptly and keep a log of every request. If an issue is found, acknowledge it, understand the root cause and agree on an action plan; arguing with evidence rarely helps.

## After the audit

Track findings to closure with owners and dates, retest fixes and capture lessons learned. The best preparation for next year's audit is acting on this year's findings.

## The bigger shift

Mature organisations move towards **continuous compliance**: evidence collected automatically and controls monitored all year, so audit readiness is a normal state, not a project.

**Key takeaway:** Prepare evidence before you are asked for it. Readiness is a habit, not a sprint.
