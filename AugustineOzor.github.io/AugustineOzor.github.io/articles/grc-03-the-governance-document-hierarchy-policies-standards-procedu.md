Governance is written down in layers. Each layer has a different purpose, audience and level of detail.

## The four layers

- **Policies** state *what* the organisation requires and *why*. They are short, high-level, approved by leadership and rarely change. Example: "All access to patient data must be authorised and reviewed."
- **Standards** make policies measurable by setting specific, mandatory requirements. Example: "Passwords must be at least 14 characters; multi-factor authentication is required for all remote access."
- **Procedures** describe *how* to do something, step by step, so it is done the same way every time. Example: the steps for granting, reviewing and removing a user's access.
- **Guidelines** offer recommended practice where flexibility is acceptable. They are advisory, not mandatory.

## Why the hierarchy matters

Keeping the layers separate keeps documents usable. A policy stuffed with technical settings must be re-approved by leadership every time a setting changes. A procedure with no policy behind it has no authority.

Auditors trace this chain. They start from the policy, check that standards make it specific, confirm procedures exist to carry it out, and then test evidence that the procedures were followed.

**Key takeaway:** Policies set intent, standards set the bar, procedures make it repeatable. Write each at the right level.
